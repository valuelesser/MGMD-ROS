## 2. 需要重点审阅的 4 处

### 2.1 ⚠️ `detector_node.py`：MFE 参数覆盖（唯一改动了主链路）

**位置**：`__init__` 里 `cfg.validate()` 之前。

**原代码的问题**：只覆盖了 `threshold` 和 `adaptive_thresh` 两个参数，但实测**真正的瓶颈是 `median_blur`**（关掉后候选帧占比 19%→53%）。

**现在改成表驱动**：

```python
for pname, field, cast in (
    ("~mfe_threshold",   "threshold",       int),
    ("~mfe_adaptive",    "adaptive_thresh", int),
    ("~mfe_median_blur", "median_blur",     int),
    ("~mfe_mode",        "mode",            str),
):
    raw = gp(pname, -1 if cast is int else "")
    ...
```

**哨兵规则**：整数参数 `-1` = 不覆盖，`>=0` 才覆盖。这样 `_mfe_adaptive:=0` 能正确关掉自适应（之前写成 `!= sentinel` 会漏掉 0，是个 bug，已修）。

**已实测验证**：

| 启动方式 | 输出 |
|---|---|
| 默认 | `MFE preset=recommended mode=3frame_or thr=5 adaptive=True` ✅ 无覆盖 |
| 全传 | 四条 `覆盖 MFE ...` WARN，`mode=2frame thr=3 adaptive=False` ✅ 全部生效 |

**风险**：默认行为完全不变，实机/离线不受影响。

### 2.2 `scripts/ros_env.sh`（新增）：公共环境与进程管理

**为什么抽出来**：三个脚本原来各自重复「设环境变量 + 杀进程」，而这部分正是最容易出错的：

- `pkill -f` 会杀掉调用它的 shell（本次会话踩了 **4 次**）
- `PYTHONUNBUFFERED` 漏设 → 日志全被吞，误判为「节点没启动」
- Gazebo 三个变量漏设 → world 静默不加载

**核心防护**（`_kill_pid`）：

```bash
case "$(ps -o comm= -p "$p" 2>/dev/null)" in
  bash|sh) return 0 ;;   # 绝不杀 shell 自己
esac
```

**请重点看**：这个 `bash|sh` 判断是否是足够的安全边界。

### 2.4 `CMakeLists.txt`：worlds 加入 install

```cmake
install(DIRECTORY launch config worlds
  DESTINATION ${CATKIN_PACKAGE_SHARE_DESTINATION})
```

**注意**：`install(DIRECTORY)` 只在 `catkin_make install` 时生效，devel 空间（我们用的）不会拷贝。`rosrun`/`roslaunch` 直接读源目录，所以功能上无影响 —— 这是为将来打包预留的。

## 4. 已知的测量陷阱（写代码时要避开）

这些是本次会话实际踩过的，全部有实测支撑：

| 陷阱 | 症状 | 正确做法 |
|---|---|---|
| `rospy.wait_for_message` 拿缓存帧 | 误判「91% 帧重复，渲染只有 3 fps」 | 用 `Subscriber(queue_size=1)` |
| `pkill -f` / `pgrep -f` | 杀掉执行命令的 shell 自身 | PID 文件 + `ps -o comm=` 判断 |
| 不设 `PYTHONUNBUFFERED` | roslaunch 下零日志，误判节点没启动 | 全局设 export |
| `kill -9` 关 visualize | mp4 损坏（`moov atom not found`） | `kill -TERM` |
| Gazebo 相机 `noise stddev=0.007` | 静止场景差分 max=19、11 万像素>3 | 仿真时关掉噪声 |
| `medianBlur(5)` | 细窄差分带被滤没，候选 19% | 仿真时设 0 |
