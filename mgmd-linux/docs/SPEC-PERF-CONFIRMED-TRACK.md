# 已确认轨迹跳过 LAC/LAD 实验规格

`spec_version: 0.1.0` · `branch: perf-confirmed-track-skip` · `base: master@5b61607`

## 1. 规则

在双路 CUDA `parity` 模式下，`confirm_frames:=3` 要求同一 TF ID 连续三个源帧均输出有效 LAD 检测。确认前，源帧号跳跃或未检测到该 ID 会清零连续计数。`confirm_frames:=0` 为逐帧复核基线，默认使用该模式。可将门槛调整为其他至少为 2 的整数。

确认后，仍由 MFE 提供候选，TF 负责关联。对 TF 当前输出中的已确认 ID，直接用本帧 TF 框及上一次真实 LAD 置信度，跳过该目标的 LAC 和 LAD，发布 `source=tf`。同帧其他目标继续走原有模型路径。如果整帧均可复用，则省掉该帧的模型输入预处理。空结果、轨迹消失或换 ID 需要重新确认。复用的框不会给未确认轨迹增加确认次数。当前实验无周期模型复核，错误关联或框漂移可能延续。

确认只在 ROS 主线程按输出帧序更新，两路计算共享只读快照。已提交的帧可能先于前序帧的确认或撤销生效，因此切换点会受在途窗口影响；撤销后，已在途的复用结果不能重新确认轨迹。

## 2. 验证

用 `phantom30` 1920×1080、`30000/1001` 源帧率、Windows FFplay、透明 CUDA HUD、12 窗口预热、无锁双路空闲派发顺序回放。两组只切换 `confirm_frames:=0` 与 `confirm_frames:=3`。统计 TF 输出目标数、复用目标数、实际 FPS、实时跳过、各阶段计时及源帧到 ROS 发布延迟。检测框来源用 `source` 区分，避免将 TF 复用置信度理解为本帧模型输出。

| 指标 | 逐帧复核 | 连续三帧确认后复用 |
|---|---:|---:|
| 处理 / 跳过窗口 | 914 / 582 | 1,165 / 331 |
| 实际 FPS | 18.28 | 23.30 |
| 源帧到 ROS 发布 P95（ms） | 236.02 | 197.22 |
| MFE / TF / LAC / LAD 均值（ms） | 48.75 / 3.56 / 8.67 / 35.01 | 43.28 / 3.42 / 9.35 / 18.69 |
| TF 轨迹行 / 复用行 | 64,576 / 0 | 84,737 / 802 |
| 有结果的窗口 | 698 | 936 |
| 有复用的窗口 | 0 | 802 |
| 有序发布队列采样峰值 | 3 | 4 |

各跑一轮，均读取 1,498 帧。复用覆盖实验组约 69% 的处理窗口和约 0.95% 的 TF 轨迹行。LAD 平均耗时下降约 47%，LAC 本轮未下降。实时选中的帧不同，未逐帧比较检测框、跟踪 ID 或准确率，不能以有结果窗口数推断精度。状态检查覆盖连续源帧门槛、丢帧断开、复用延续、消失撤销，以及过期复用不会重新确认。详见 [运行摘要](../outputs/confirmed_track_skip_20261117/_summary.json)。
