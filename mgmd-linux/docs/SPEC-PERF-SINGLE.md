# SPEC-PERF-SINGLE · ROS GPU 单流优化

`spec_version: 0.1.10` · `branch: perf-single-stream` · `base: perf-optimization@bd0da6b`

## 1. 范围与基线

从两流 HUD 版本分支，先用现有 `track_gpu.launch` 的 `legacy` 模式建立单流基线。MFE、TF、LAC、LAD 在同一应用计算路径按帧串行推进。此定义不约束 NVDEC、OpenCV 或 ONNX Runtime 内部使用的流。HUD 继续显示处理 FPS、四阶段及 MFE 分项的近两秒均值。

基线用现有 `mgmd-ros` 容器及 `phantom30` 1080p 视频，维持 30 Hz、rqt/HUD。记录明确的解码器、warp、选帧及计时设置。固定帧序列用于对拍候选、跟踪 ID、检测框和置信度。实时全片记录读帧、处理、跳过、FPS、发布延迟 p50/p95，以及分项耗时均值和 p95。两流历史结果仅作参考，后续单流改动使用本分支同配置基线比较。

### 1.1 首轮实测

```bash

  decoder_backend:=opencv decoder_leading_frames:=25 profile_wall:=true
```

1080p、30 Hz、rqt/HUD 和 MFE 分项计时开启。沿用 OpenCV GPU 解码环境，25 帧偏移只适用于本次 `phantom30`。单流 `legacy` 路径未开启灰度复用。2026-11-13 全片读取 1,498 帧，处理 561 个窗口，跳过 935 个，398 个窗口有检测。运行 49.982 s，处理速率 11.22 FPS，源帧到 ROS 发布延迟 p50/p95 为 118.28/151.18 ms。

|---|---:|
| MFE | 33.78 / 40.68 |
| TF | 2.27 / 3.29 |
| LAC | 6.17 / 13.02 |
| LAD | 28.03 / 43.08 |

MFE 子阶段均值分别为灰度 4.47、LK 3.23、RANSAC 9.38、warp 4.49、差分与阈值及中值 2.91、形态学 4.20、连通域 0.46、区域统计 3.85 ms。原始日志在容器 `outputs/single_stream_20261113/launch.log`。

### 1.3 单流跨窗口灰度复用

默认 `reuse_gray:=true`。单流将三个源帧的实际序号传给既有 MFE 灰度缓存，只保存上一处理窗口的三张 GPU 灰度图。缓存随流水线实例创建。跳帧时仅复用实际重叠的帧，差分及检测算法保持原配置。用 `reuse_gray:=false` 复现 §1.1 和 §1.2 的无缓存配置。

沿用 §1.1 的 1080p、30 Hz、rqt/HUD、OpenCV 解码及 warp 配置，先关后开各跑一轮，均读取 1,498 帧到 EOF。

| 指标 | 关闭 | 开启 |
|---|---:|---:|
| 处理 / 跳过窗口 | 787 / 709 | 869 / 627 |
| 处理 FPS | 15.75 | 17.39 |
| 灰度均值 / p95（ms） | 4.452 / 4.405 | 2.429 / 3.011 |
| MFE 均值 / p95（ms） | 28.99 / 31.09 | 25.67 / 29.25 |
| 发布延迟 p50 / p95（ms） | 103.58 / 126.32 | 101.81 / 123.40 |

固定帧对拍覆盖 130 个连续或带跳号的窗口，有序候选框及分数逐元素一致。实时 A/B 各运行一次，选帧随吞吐变化。原始日志在容器 `outputs/single_gray_20261113/{false,true}.log`。

### 1.4 奇偶中心帧实验

`pipeline_mode:=parity` 按源中心帧序号的奇偶分配 MFE、LAC 和 LAD。两路各用独立的 CUDA 流、LK 对象和推理会话，共享解码源及派发端的上一窗口灰度缓存。TF 由单一 CUDA 流和工作线程按接纳顺序更新同一份状态，发布同样按接纳顺序。每帧继续使用原视频中前后紧邻的源帧。派发沿用源时钟过期判断，最多两个窗口在途，接纳后不再淘汰。OpenCV 默认流和 ORT 保留共享保护锁。单流仍为默认入口。

按 §1.1 配置开启灰度缓存，单流与奇偶两路均读完 1,498 帧。单流处理 863 个窗口、跳过 633 个，17.28 FPS，发布 p50/p95 100.71/125.39 ms。奇偶处理 1,018 个窗口、跳过 478 个，20.36 FPS，发布 p50/p95 131.53/163.51 ms。奇偶 MFE、TF、LAC、LAD 均值为 41.29、2.89、6.91、25.56 ms。固定帧含跳号，71 个窗口的发布帧序、候选数量、检测数量及输出 ID 一致。该检查未覆盖坐标和置信度的数值等价。容器证据为 `outputs/parity_20261113/{legacy,parity_retry}.log`。

### 1.5 按接纳顺序分配双路

沿用实验入口 `pipeline_mode:=parity`。改为按已接纳窗口交替分配，因此在途的两个窗口始终分属两路。原源帧号继续用于共享灰度缓存、TF 和 ROS 发布，源时钟跳帧仍在派发前执行。保留 OpenCV 默认流和 ORT 的共享保护锁。

同 §1.4 条件全片复测，读 1,498 帧、处理 1,042、跳过 454，20.85 FPS，发布延迟 p50/p95 为 128.97/162.13 ms。旧奇偶策略为 20.36 FPS，本次为独立单轮，尚未通过重复 A/B 隔离小幅收益。容器日志为 `outputs/parity_round_robin_20261113/launch.log`。

### 1.6 NPP 连通域与去锁实验

在双路入口可用 `npp_ccl:=true` 试 CUDA 12 NPP 八连通标记，每路绑定自己的 CUDA 流与工作缓冲。容器需将 `/usr/local/cuda/lib64` 加入库搜索路径。NPP 给所有同值连通区域编号，含背景，也可能给前景编号 0；读取前景标签后偏移 1，再走原区域统计。固定 120 个窗口仍有 47 个窗口的有序候选框或分数不同，未达到等价验收。

直接移除保护锁曾触发 ORT `cudaDeviceSynchronize` 的 CUDA 900。最终 `npp_unlocked:=true` 同时将 LAC/LAD 改为各自 CUDA 流同步，一轮全片完成。该结果未证明其他序列或重复运行下无捕获冲突。默认继续用 OpenCV CCL 与保护锁。

| 1080p、30 Hz、rqt/HUD、双路 | 处理 / 跳过 | FPS | CCL 均值 / p95（ms） | 发布 p95（ms） |
|---|---:|---:|---:|---:|
| OpenCV，有锁 | 1019 / 477 | 20.39 | 2.52 / 5.35 | 163.19 |
| NPP，其余操作保留锁 | 779 / 717 | 15.58 | 14.23 / 15.36 | 195.84 |
| NPP，无共享锁、各流同步 | 803 / 693 | 16.06 | 14.20 / 15.31 | 184.37 |

均读取 1,498 帧。日志在容器 `outputs/npp_ccl_final_20261113/{false-false,true-false}.log` 与 `outputs/npp_ccl_20261113/unlocked_stream_sync.log`。

### 1.7 显式流 BUF 连通域

实验仅替换双路 CCL。独立 CUDA 实现采用 [BUF 的 2×2 分块思想](https://iris.unimore.it/handle/11380/1179642)，每块内部的前景像素在八连通下属于同一分区。通过跨块邻边合并分区，最后生成背景为 0 的标签图。每路预分配父节点和标签缓冲，三个 kernel 都提交到本路流，区域统计依靠流内顺序读取。解码和 ORT 保留保护锁。

```bash
/usr/local/cuda/bin/nvcc -O3 -arch=sm_86 -shared -Xcompiler -fPIC \
  mgmd_onnx/cuda_buf_ccl.cu -o /tmp/mgmd-buf-ccl.so
roslaunch mav_tracker_nodes track_gpu.launch pipeline_mode:=parity \
  buf_ccl_library:=/tmp/mgmd-buf-ccl.so warp_backend:=opencv \
  decoder_backend:=opencv decoder_leading_frames:=25 profile_wall:=true
```

同条件 1080p、30 Hz、rqt/HUD 各跑一轮，均读 1,498 帧。OpenCV / BUF 分别处理 950 / 996 个窗口，19.00 / 19.93 FPS，发布延迟 p95 175.15 / 170.41 ms，CCL 事件区间均值/p95 为 2.80/6.44 和 0.88/1.31 ms。该区间含同步与等待。120 个真实掩膜的前景八连通分区和有序候选框、分数完全一致。各跑一轮，实时选帧不同，尚未用 trace 确认 CCL 与 LAD 内核重叠。容器日志 `outputs/buf_ccl_20261113/{opencv,buf}.log`。

### 1.8 BUF 双路解除共享锁

在 §1.7 命令加 `buf_unlocked:=true`。解码、共享灰度准备和 ORT 提交跳过应用层共享互斥。解码与灰度准备由同一派发线程推进，跨流依赖继续用 CUDA event。LAC/LAD 沿用设备 I/O Binding，关闭 ORT 执行提供器结束同步，在各自的 CUDA 流上等待输出。该开关默认关闭。

1080p、30 Hz、rqt/HUD 全片，两组均读取 1,498 帧。保留锁和解除锁分别处理 957 / 1,068 窗口，19.15 / 21.37 FPS，发布 p95 为 178.21 / 156.91 ms。LAD 均值为 29.90 / 24.58 ms。每组各一轮，选帧随吞吐变化。另以相同的 120 个窗口对拍，源帧顺序、候选数量、检测数量、ID 和框坐标一致，置信度最大绝对差 0.00064844。运行证据为容器 `outputs/buf_unlocked_20261113/{false,true}.log`。此 A/B 同时改变应用锁和 ORT 完成同步方式，尚未通过 GPU trace 验证内核重叠。

### 1.10 BUF 无锁三路

在 §1.8 的无锁 BUF 配置加 `parity_lanes:=3`，每路独立执行 MFE、LAC 和 LAD。共用解码、灰度缓存和按源帧顺序推进的 TF。按接纳顺序轮转分配，最多三个检测窗口在途。默认仍为两路。此处“三路”指三条帧计算流，另外还有共享的 TF 流。

同一容器、1080p、rqt/HUD、OpenCV 解码及 warp、灰度复用。每种配置各跑一轮，读取 1,498 帧。实时对照按 30 Hz 源时钟选帧，不限速对照处理相同的全部 1,496 个中心窗口。整卡指标每 200 ms 采样。

### 1.11 播放前预热

在单流或双路启动命令加 `warmup_frames:=12`，默认 0。启动播放时钟前预读最多 14 张源图像，用前 12 个窗口走实际 MFE、TF、LAC 和 LAD 路径。预热不发布 ROS 消息。完成后重置 TF、清空预热灰度缓存，再将预读帧按原序交给正式回放。原有实时跳帧判断照常执行。预热只能覆盖这些窗口遇到的 LAC 形状。

无锁 BUF 双路以 1080p、30 Hz、rqt/HUD 各跑一轮，均正式读取 1,498 帧。预热耗时 4.165 s。自播放时钟启动到首次发布由 739.32 降为 124.91 ms，前 3 秒发布由 2 增为 58 个窗口，全片为 18.94 / 19.96 FPS，发布延迟 p95 为 173.98 / 186.85 ms。预热主要改善播放开头，首次画面需加上播放前的预热等待。容器日志为 `outputs/warmup_20261113/{0,12}.log`。
