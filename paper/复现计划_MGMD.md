## 一、论文方法回顾（复现对象）

三个模块串行：

| 模块 | 作用 | 关键实现细节（论文给出） |
|---|---|---|
| **MFE** 运动特征增强 | 从复杂背景中分割运动候选 | 网格关键点 + 金字塔 LK + RANSAC 求单应；当前帧与前后各 k 帧配准后做差分；阈值 5 二值化；两路 **逻辑或** 聚合；3×3 开闭运算；连通域 < 15 像素剔除；最小外接矩形 |
| **TF** 轨迹过滤 | 剔除视差/抖动误检 | SORT（卡尔曼匀速模型 + 匈牙利匹配），IOU 关联阈值 0.3，max_age=3，min_hits=1；对间隔 3 帧的框先做透视对齐，再用 D=ρ/d 判据，D≥1 判为运动目标 |
| **局部精检测** | 剔除相似运动的其他物体并精修框 | LAC：3 层 CNN，输入 32×32，ReLU+MaxPool，softmax 二分类，Adam lr=0.001，100 epochs，batch=64；LAD：YOLOv5s + 小目标检测层，在候选中心裁 320×320，置信度 0.5，Adam momentum 0.937，lr=0.01，MS-COCO 预训练 |

评测：IOU 阈值 0.25，指标 P/R/F1/AP，ARD-MAV 数据集（60 视频、106,665 帧、1920×1080、30 FPS），50 训练 / 10 测试。
论文结果：P 0.84 / R 0.59 / F1 0.69 / AP 0.55 / 28 FPS（RTX 3070）。

### GLAD 仓库能直接复用的部分

- `Functions.motion_compensate()`：网格 KLT + RANSAC 单应 + `warpPerspective` + 有效区掩膜 —— 与论文 III-A1 几乎一致，可直接改写为 MFE 的配准步骤。
- `MOD2_global/local()`：两帧差分 + 形态学 + 运动一致性筛框 —— 可作为 **Table II 中 "2-frame" 基线**，也是 MFE 的参照实现。
- `Functions.Net` + `weights/Net_best.pth`：2 层卷积 + 3 层全连接的 32×32 二分类器 —— 功能对应 LAC（论文称"3 层 CNN"，结构略有差异），可直接用或作为预训练起点。
- `video2img.py`：视频抽帧脚本。
- `detector*_trt.py` + `.engine`：TensorRT 版本（Linux + `libmyplugins.so`），**Windows 上不能用**；改用 `.pt` + YOLOv5 v6.0 的 PyTorch 推理。

## 三、复现可行性判断

| 模块 | 可行性 | 主要依据 / 风险 |
|---|---|---|
| 数据准备 | **高** | 标注已到手；视频需百度网盘下载（约数十 GB），需校验帧数与 XML 一一对应 |
| MFE | **高** | 论文参数基本给全（阈值 5、3×3、15 像素）；GLAD 有同源实现可对照。唯一缺口：**帧间隔 k 未给出** |
| TF | **高** | SORT 是成熟开源实现（`abewley/sort`），D 判据公式明确；只需补"对齐后再算距离"的细节 |
| LAC | **中高** | 网络结构/超参明确，但**正负样本如何采样未说明**；可用 MFE 候选框 + 标注自动生成训练集 |
| LAD | **中** | YOLOv5s v6.0 可复现；"小目标检测层"具体接哪几层、怎么 concat **未说明**，需按常见做法（P2 层）自行设计 |
| 指标对齐 | **中低** | 测试集划分未公开（只知 50/10，不知具体视频 ID）、AP 计算方式未说明 → **数值不可能逐位对齐**，只能复现趋势与量级 |
| 速度对齐 | **低** | 论文为 RTX 3070 + 可能 TensorRT；本机 3050 4 GB 且无 TensorRT → FPS 会明显偏低，不具可比性 |

**结论：可以做，属于"方法级复现 + 趋势验证"，不是"数字级复现"。**
核心算法（MFE + TF）有论文参数和同源代码支撑，风险可控；LAC/LAD 需要自行补全训练细节；最终指标应报告"自建划分下的结果"，并明确与原文不可逐项比较。

## 四、必须提前接受的 5 个"对不上"缺口

1. **帧间隔 k 未给出**：只能做敏感性实验（k=1/2/3/5），选一组自洽值并在报告中声明。
2. **测试集划分未公开**：GLAD README 给出的 15 个测试视频（05/08/09/10/19/30/41/43/46/47/58/63/65/70/86）是 GLAD 的划分，不是 MGMD 的 10 个。建议固定一套划分并全程复用，保证自身消融可比。
3. **LAC 训练样本构造未说明**：需自定义（建议正样本=与 GT IOU>0.25 的候选，负样本=其余候选，按视频划分避免泄漏）。
4. **"小目标检测层"细节缺失**：论文只说"将浅层特征图与深层特征图 concat"。建议按 YOLOv5-P2 常见做法实现，并单独做消融说明这是推断。
5. **AP 定义与 FPS 口径不明**：AP 是按帧累积还是按视频？FPS 是否含预处理？报告中需写明自定口径。

## 五、分阶段实施计划

### 阶段 0：环境与数据（约 3–5 天）

- [ ] 安装 Miniconda（Python 3.9/3.10）→ 创建 `mgmd` 环境
- [ ] 安装 PyTorch 2.x + CUDA 12.1、OpenCV、numpy、filterpy、torchvision
- [ ] 克隆 `ultralytics/yolov5`（**v6.0 分支**，与 GLAD 权重匹配）与 `abewley/sort`
- [ ] 安装 ffmpeg（抽帧用）
- [ ] 从百度网盘下载 ARD-MAV 视频；与 HuggingFace 标注按文件名对齐
- [ ] 建立数据清单：视频 ID、帧数、有标注帧数、目标尺寸分布
- [ ] **验收**：任取 1 个视频，抽帧后能正确读到对应 XML，框可视化位置无误

### 阶段 1：MFE 实现（约 4–6 天）

- [ ] 网格关键点采样（参考 GLAD：1920×1080 上约 19×14 网格；论文写 30×20，做对比）
- [ ] 金字塔 LK + RANSAC 求 H；当前帧分别与 `t-k`、`t+k` 配准
- [ ] 双路差分 → 阈值 5 → 二值化 → 逻辑或
- [ ] 3×3 开、闭运算（记录迭代次数的影响）
- [ ] 连通域分析，剔除 < 15 像素；最小外接矩形输出
- [ ] **验收（关键闸门）**：在 2–3 个视频上统计 **候选召回率**（GT 框是否被候选覆盖，IOU>0.25）。目标 ≥ 70%；若过低，先排查配准/阈值，再进入下一阶段

### 阶段 2：TF 实现（约 3–5 天）

- [ ] 接入 SORT（IOU 0.3、max_age=3、min_hits=1）
- [ ] 实现轨迹分类：取 `s_{N-3}` 透视对齐到 `s_N`，算 D=ρ/d，D≥1 保留
- [ ] 统计剔除前后的候选数量、召回变化
- [ ] **验收**：能复现论文 Fig. 4 的定性效果（灯柱/树木误检被大量剔除，车辆/行人/MAV 保留）

### 阶段 3：LAC 实现与训练（约 4–6 天）

- [ ] 用 MFE+TF 输出自动生成候选裁剪（32×32），按 GT 打正负标签
- [ ] 实现 3 层 CNN（或直接复用 GLAD `Net` 结构），Adam lr=0.001、100 epochs、batch=64
- [ ] 按视频划分训练/验证，避免同视频泄漏
- [ ] **验收**：验证集二分类准确率、正样本召回；给出混淆矩阵

### 阶段 4：LAD 实现与训练（约 7–10 天）

- [ ] 以 `yolov5s_GLAD-crop.pt` 或 MS-COCO `yolov5s.pt` 初始化
- [ ] 在候选中心裁 320×320 训练（正样本=GT 落在此区域）
- [ ] 尝试加入 P2 小目标检测层（浅层+深层 concat），做有无对比
- [ ] 4 GB 显存配置：`--batch 8 --img 320`，必要时梯度累积；先抽 1/3 帧训练验证流程
- [ ] **验收**：验证集 mAP@0.25；单帧局部推理耗时

### 阶段 5：端到端评测与消融（约 5–7 天）

- [ ] 实现评测脚本：IOU 0.25，逐帧 P/R/F1，AP（写明计算口径）
- [ ] 复现 Table II（2-frame / 3-frame+AND / 3-frame+OR）
- [ ] 复现 Table III（MFE、TF、LAC、LAD 的组合消融）
- [ ] 记录 FPS（CPU / GPU 各一组，注明是否含预处理）
- [ ] **验收**：主表 + 两张消融表；与论文趋势一致（OR > AND > 2-frame；LAC/LAD 提升精度）

### 阶段 6：分析与扩展（约 5–7 天，毕业设计的加分项）

- [ ] 复现论文已知缺陷：悬停/慢速目标漏检、多目标只取单目标、类 MAV 干扰物（鸟/车）误检
- [ ] 针对毕设做一个小改进并量化（任选其一）：
  - 自适应阈值（用局部对比度替代固定阈值 5）
  - 加入 P2 层 + 切片推理（SAHI 思路）提升小目标
  - 用轻量跟踪替代 SORT 以降低延迟
- [ ] 整理失败案例图、参数敏感性曲线（k、阈值、形态学核、15 像素门限）

### 阶段 7：写作与归档（约 5 天）

- [ ] 复现报告：环境、数据、实现偏差、结果表、与原文对比、失败分析
- [ ] 代码整理为可运行仓库（配置化路径/参数），附 README
- [ ] 明确声明哪些细节是推断、哪些数字不可比

## 七、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 百度网盘下载慢/限速 | 数据准备拖延 | 优先下 10–15 个视频先跑通；标注已齐全，可先做 MFE 调参 |
| 4 GB 显存不足 | LAD 训练 OOM | batch 8 + 320 输入 + 梯度累积；或冻结主干只训检测头；必要时租云端 GPU 只训 LAD |
| 无 TensorRT | FPS 远低于论文 | 报告 PyTorch FP32/FP16 两组，注明硬件差异；不把 FPS 作为复现成功标准 |
| 候选召回不足 | 后续模块全崩 | 阶段 1 设闸门；优先调 k、阈值、形态学核；用 GLAD 的 `MOD2` 做对照定位问题 |
| 指标对不上原文 | 无法宣称"复现成功" | 统一口径、报告自建划分；强调趋势一致 + 消融可复现，而非绝对值 |
| 论文细节缺失 | 实现偏差 | 每个推断点在报告中标注"推断/自定"，并做敏感性实验 |

## 九、一句话结论

**这篇论文可以复现，但只能做"方法级复现"：** 核心的 MFE 与 TF 有完整参数和同源代码支撑，数据标注也已公开可得；真正卡住"数字对齐"的是未公开的测试划分、帧间隔 k、LAC 采样方式和 LAD 小目标层细节。建议先花 3 天做"2 个视频 + MFE 候选召回"的试点，验证数据与配准链路后再投入完整实现。
