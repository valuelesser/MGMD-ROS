# SPEC-PERF-IMU · 单流 GPU IMU 对齐实验

版本 0.1.0。分支 `exp/gpu-imu-mfe`，基线 `master@5b61607`。

## 实验口径

使用同一相机的 rosbag 图像和 IMU 消息，确保两种方式处理完全相同的三帧窗口。MFE 路径分别采用 GPU LK+RANSAC 和仅 GPU IMU。IMU 时间戳搜索、四元数插值、坐标系转换、相对旋转和单应矩阵计算均在 GPU 上。主机读取 bag 和标定、传入原始数据。相机平移和未提供的镜头畸变参数不纳入模型。

后端执行 MFE → TF → LAC → LAD，沿用 GPU 灰度缓存、OpenCV CUDA warp、BUF 连通域、流内 ORT 推理及 CUDA HUD。两个方案分别使用同样的一条 CUDA 计算流。预热后在每段重置跟踪与灰度缓存，保留帧序。分段记录计算耗时与包含预览的处理吞吐，注明输入、预热、I/O 与发布边界。

以 LK+RANSAC 的最终检测结果为参考，公布相同帧上的框匹配率、单边输出、匹配框 IoU、中心偏移和置信度差。匹配限同帧，IoU 阈值为 0.5，每框最多匹配一次。没有标注时只报告路径一致性，不报告真实准确率、召回率或 mAP。

## 维护与验收

沿用 [主分支 GPU 规格](SPEC-PERF-GPU.md) 和仓库维护约定。每次功能改动更新版本、修改原因、命令、验收结果和已知限制。实现、SPEC 与可提交的 JSON 摘要同次提交，不提交标定原件、bag、模型和构建产物。提交前检查改动范围及 `git diff --check`，完成对应测试。提交后检查 `git show --stat HEAD`，推送本实验分支并核对远程哈希。实验结果与失败一并保留。

## 运行方式

在 Docker ROS Noetic 中加载 ROS 工作区环境，按 [主分支 GPU 规格](SPEC-PERF-GPU.md) 准备 OpenCV CUDA、ORT、模型和三份动态库。在 `mgmd-linux` 下执行：

```bash
PYTHONPATH="$PWD:$PYTHONPATH" python3 scripts/compare_gpu_imu_mfe.py \
  /tmp/mgmd-align-camera.yaml /tmp/mgmd-imu-full-pipeline-expanded.json \
  --duration 12 --offsets 15 50 85 \
  --bag 1 /data/ros_bag/uav1/uav1_onboard_20260729_190542_1.bag \
  --bag 2 /data/ros_bag/uav2/uav2_onboard_20260729_190547_1.bag
```

使用 YAML 第一组和第二组内外参分别对应 UAV1/TEMP1、UAV2/TEMP3。按 `/mavros/imu/data` 消息头时间戳插值，单次插值跨度上限 50 ms；两路径共用通过覆盖和相邻帧间隔检查的窗口。姿态用 GPU 批量预计算，帧序下标用于读取 GPU 上的正反向采样矩阵。为保证输入完全一致，片段从 bag 读取后预载到显存。FPS 包含 MFE、TF、LAC、LAD、检测回读、CUDA HUD 和 ROS 图像载荷构造，IMU 路径另加 GPU 批量预计算时间。计时范围不含文件 I/O、输入预载、预热、ROS 传输或显示器呈现。各段预热并重置 TF 和灰度缓存，交替两路径的运行次序。

## 实测结果

前置对照在 679 个三帧窗口上比较过实际 warp 采样坐标。以视觉对齐为基准，UAV1/UAV2 的逐方向典型偏差 P50/P95 分别为 0.22/0.51 px 和 0.46/1.14 px。纯 IMU 的 MFE 前景像素分别增加 14.7% 和 35.8%。首轮全流程短片只有 5 个 LK 最终框，因此扩大到两架机各三个 12 秒的片段。

| 640×480 | 配对窗口 | LK / IMU FPS | LK / IMU MFE 平均 ms | LK / IMU 最终框 | 匹配 / LK 未匹配 / IMU 未匹配 |
|---|---:|---:|---:|---:|---:|
| UAV1 | 1,087 | 82.29 / 149.31 | 9.09 / 3.91 | 22 / 22 | 6 / 16 / 16 |
| UAV2 | 1,086 | 74.16 / 105.06 | 9.04 / 4.00 | 20 / 27 | 3 / 17 / 24 |
| 合计 | 2,173 | 78.02 / 123.34 | — | 42 / 49 | 9 / 33 / 40 |

两路均无最终框的窗口为 2,097 个。只有 LK 输出框的窗口为 29 个，只有 IMU 输出框的窗口为 36 个。9 个匹配框的中心偏移中位数为 0 px，UAV1 的 6 个匹配中 P95 为 0.875 px，UAV2 的 3 个匹配完全重合。以 LK 为参照，42 个框中只匹配上 9 个。可表达为 21.4% 的参考框匹配率，检测准确率仍待带标注数据评测。IMU 在本实验有吞吐收益，最终检测输出差异较大。详细分段数据见 [运行摘要](../outputs/gpu_imu_mfe_20261118/_summary.json)。

已知旋转的 GPU 数值校验覆盖四元数符号翻转、时间插值、前后 warp 方向和时间戳越界。该校验和两种对齐的实际 CUDA 全链路回放均通过。
